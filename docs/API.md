# AttendX REST API Reference

The AttendX API is versioned and hosted at `/api/v1`. All protected endpoints require a Bearer token in the `Authorization` header.

## Authentication
`POST /api/v1/auth/register`
Creates a new user. Passwords must be strictly strong.

`POST /api/v1/auth/login`
Authenticates a user and returns a signed JWT alongside basic profile data.

## Attendance Engine
`POST /api/v1/attendance/sessions`
**(Faculty Only)** Creates a new Attendance Session for a specific Subject and Class. Allows toggling `isFaceRecognitionEnabled` and `isQREnabled`.

`POST /api/v1/attendance/mark/qr`
**(Student Only)** Submits a dynamically rotating cryptographic QR token generated by the Faculty's dashboard. Marks the student as `PRESENT`.

`POST /api/v1/attendance/mark/face`
**(Student Only)** Submits a mathematical face embedding array generated by `@vladmandic/face-api`. The backend calculates Euclidean distance against the registered profile tensor to verify identity.

## Analytics & Reporting
`GET /api/v1/analytics/student/:studentId`
Returns aggregated attendance percentages grouped by subject, generating warnings if the threshold drops below 75%.

`GET /api/v1/reports/student`
Returns a streamable CSV, XLSX, or PDF (via `pdfmake`) detailing the exact timestamp of every session attended.

## Security Controls
- **Rate Limiting**: Enforced via `express-rate-limit` to prevent brute force.
- **RBAC**: Handled by the `requireRole(['ADMIN', 'FACULTY'])` Express middleware.
- **Payload Validation**: Strict enforcement via `Zod` schemas.
