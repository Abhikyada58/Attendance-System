# AttendX Database Schema

AttendX uses PostgreSQL, managed via Prisma ORM. Below is an overview of the core entities and their relationships.

## Core Entities

### User
The foundational authentication model.
- Contains credentials (`passwordHash`) and roles (`STUDENT`, `FACULTY`, `ADMIN`).
- Tracks biometric data securely (`faceEmbeddings`).

### Academic Structure
- **Institute & Department**: The root hierarchies.
- **Subject & Class**: The containers for academic activity. A Faculty member manages a Class taking a specific Subject.

### Attendance Core
- **AttendanceSession**: A time-bounded block generated by a Faculty member (e.g. "Database Systems, 10:00 AM - 11:00 AM"). Contains a rotating `qrSecret` for cryptographic security.
- **AttendanceRecord**: Represents a single Student successfully verifying their presence inside a Session. Tracks the exact `timestamp` and `method` (`MANUAL`, `QR`, `FACE`).

## Cascading Behaviors
Prisma is configured to strictly handle deletions. If a `User` is deleted, all their associated `AttendanceRecord`s are wiped to ensure GDPR/Data-Privacy compliance. If a `Class` is dropped, all associated `AttendanceSession`s are removed.

## Future Schema Scaling
Because the `AttendanceRecord` table will grow massive over time, it is indexed on `(sessionId, studentId)` to ensure analytical reads and duplicate-check queries remain O(1) instantaneous regardless of scale.
